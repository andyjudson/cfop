# Feature 023 — wca-data-refresh

## Summary

A standalone Python refresh script that downloads the WCA public export and regenerates the three WCA JSON files consumed by cfop-app, replacing the manual PySpark notebook workflow. Runnable locally with no Spark dependency, and wired to a weekly GitHub Actions schedule for automatic updates.

---

## Background

`cfop-app/public/data/` contains three derived datasets:

| File | Description |
|------|-------------|
| `wca-wr-evolution.json` | Full WR progression for 3x3x3 (single + average), all time |
| `wca-wr-legends.json` | Per-person WR count summary with current-holder flags |
| `wca-beat-the-champion.json` | Finals winners + scrambles from WR events and championships |

These were originally generated by `pyspark.sandbox/wca_parser.ipynb`. The notebook logic is clean and well-factored (`prepare_*` / `export_*` functions) but requires PySpark to run — blocking refresh after any new WR. The average WR shifted in April 2026 and the files are already stale.

The WCA publishes a full public export at `https://www.worldcubeassociation.org/export/results/v2/tsv` (~300MB zip, updated weekly). The download function already exists in the notebook; the transforms only need the 3x3x3 slice which is tiny.

## Scope

### Script: `scripts/refresh-wca.py`

A standalone Python script with no dependencies beyond `requests` and `pandas`.

**Behaviour:**
- Downloads the WCA TSV export to `.wca-cache/` (repo root, gitignored)
- Skips download if cache is fresh (same export date as metadata)
- Runs all three transforms
- Writes output to `cfop-app/public/data/`
- Prints a summary: export date, record counts, any new records vs previous files

**Invocation:**
```bash
python scripts/refresh-wca.py              # download if stale, then refresh all
python scripts/refresh-wca.py --force      # re-download even if cache is current
python scripts/refresh-wca.py --no-download  # use existing cache only
```

**Dependencies:** `requests`, `pandas` — both available in standard Python environments, no pip extras needed for CI.

### GitHub Action: `.github/workflows/refresh-wca.yml`

- **Schedule:** weekly (`cron: '0 6 * * 1'`) + manual dispatch (`workflow_dispatch`)
- **Steps:** checkout → python setup → `pip install requests pandas` → run script → commit + push updated JSON if any file changed
- **Commit message:** `chore(data): refresh WCA data (export YYYY-MM-DD)`
- No secrets needed — WCA export is public, commit uses `GITHUB_TOKEN`

## Porting Notes

PySpark constructs map cleanly to pandas:

| PySpark | Pandas equivalent |
|---------|-------------------|
| `spark.read.csv(path, sep="\t")` | `pd.read_csv(path, sep='\t')` |
| `row_number().over(Window.partitionBy(…).orderBy(…))` | `df.sort_values(…).groupby(…).cumcount()` or `rank()` |
| `f_min(col).over(Window.orderBy(…).rowsBetween(unbounded, 0))` | `df['col'].cummin()` (after sort) |
| `lag(col).over(Window.orderBy(…))` | `df['col'].shift(1)` |
| `df.filter(…)` | `df[df['col'] == …]` |
| `.toPandas()` | already pandas |
| `col("year") * 10000 + …` | `df['year'] * 10000 + …` |

The beat-the-champion transform is the most complex (4 joins, window rank for finals winner, cross-join pattern for WR-at-time). The notebook implementation is the reference — port function-by-function.
