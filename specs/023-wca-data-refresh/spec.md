# Feature 023 — wca-data-refresh

## Summary

A Poetry-managed Python package that downloads the WCA public export and regenerates the three WCA JSON files consumed by cfop-app, replacing the manual PySpark notebook workflow. Exposed as a `/refresh-wca` Claude Code skill for interactive local use, and wired to a weekly GitHub Actions schedule for automatic updates.

---

## Background

`cfop-app/public/data/` contains three derived datasets:

| File | Description |
|------|-------------|
| `wca-wr-evolution.json` | Full WR progression for 3x3x3 (single + average), all time |
| `wca-wr-legends.json` | Per-person WR count summary with current-holder flags |
| `wca-beat-the-champion.json` | Finals winners + scrambles from WR events and championships |

These were originally generated by `pyspark.sandbox/wca_parser.ipynb`. The notebook logic is clean and well-factored (`prepare_*` / `export_*` functions) but requires PySpark to run — blocking refresh after any new WR. The average WR shifted in April 2026 and the files are already stale.

The WCA publishes a full public export at `https://www.worldcubeassociation.org/export/results/v2/tsv` (~300MB zip, updated weekly). The download function already exists in the notebook; the transforms only need the 3x3x3 slice which is small.

---

## Source Notebook

`pyspark.sandbox/wca_parser.ipynb` (separate repo)

Key functions to port:

| Notebook function | Description |
|-------------------|-------------|
| `download_wca_export()` | Downloads zip, extracts TSV files, reads `metadata.json` for export date |
| `parse_results(filter)` | Joins results + competitions TSV, filters to 3x3x3 |
| `compute_wr_progression(df, type)` | Cumulative min WR over time; collapses ties per day |
| `prepare_wr_evolution()` | Runs progression for single + average, unions |
| `prepare_wr_legends(df_wr)` | Per-person aggregation: WR counts, best times, current-holder flags |
| `prepare_beat_the_champion(year)` | Multi-join: results + competitions + championships + scrambles; WR context at time |
| `export_*(dest_path)` | Writes NDJSON to dest directory |

## Scope

### Package: `scripts/wca-refresh/`

A Poetry-managed Python package. All transforms are ported from PySpark to pandas — no Spark dependency.

```
scripts/wca-refresh/
  pyproject.toml          # Poetry project: name=wca-refresh, deps: requests, pandas
  poetry.lock
  wca_refresh/
    __init__.py
    download.py           # download_wca_export(), cache freshness check
    transforms.py         # all prepare_*() functions
    export.py             # export_*() functions, diff summary
    cli.py                # entry point: argument parsing, orchestration, output
```

**CLI entry point** (registered in `pyproject.toml` as `wca-refresh`):
```bash
poetry run wca-refresh                  # download if stale, refresh all three files
poetry run wca-refresh --force          # re-download even if cache is current
poetry run wca-refresh --no-download    # use existing cache, skip network
poetry run wca-refresh --dry-run        # compute but do not write output files
```

**Output on run:**
```
WCA export date: 2026-05-05
Cache: fresh (skipping download)

Refreshing wca-wr-evolution.json   … 62 records  (+2 new)
Refreshing wca-wr-legends.json     … 26 persons  (no change)
Refreshing wca-beat-the-champion.json … 147 competitions  (+3 new)

Done. Files written to cfop-app/public/data/
```

**Cache:** `.wca-cache/` at repo root (gitignored). Stores extracted TSV files and `metadata.json`. Skip download if `metadata.json` export date matches latest available.

### Skill: `.claude/commands/refresh-wca.md`

A Claude Code skill invoked as `/refresh-wca`. Orchestrates the full flow interactively:

1. Checks `poetry` is available and `poetry install` has been run in `scripts/wca-refresh/`
2. Runs `poetry run wca-refresh` (or `--force` / `--no-download` based on args)
3. Reports the diff summary from the script output
4. Offers to commit the updated JSON files with message `chore(data): refresh WCA data (export YYYY-MM-DD)`

Usage:
```
/refresh-wca              # standard refresh
/refresh-wca --force      # force re-download
/refresh-wca --no-download  # transforms only, no network
```

### GitHub Action: `.github/workflows/refresh-wca.yml`

- **Schedule:** weekly (`cron: '0 6 * * 1'`) + manual dispatch (`workflow_dispatch`)
- **Steps:** checkout → python + poetry setup → `poetry install` → `poetry run wca-refresh` → commit + push updated JSON if any file changed
- **Commit message:** `chore(data): refresh WCA data (export YYYY-MM-DD)`
- No secrets needed — WCA export is public, commit uses `GITHUB_TOKEN`

## Porting Notes

PySpark constructs map cleanly to pandas:

| PySpark | Pandas equivalent |
|---------|-------------------|
| `spark.read.csv(path, sep="\t")` | `pd.read_csv(path, sep='\t')` |
| `row_number().over(Window.partitionBy(…).orderBy(…))` | `df.sort_values(…).groupby(…).cumcount()` or `rank()` |
| `f_min(col).over(Window.orderBy(…).rowsBetween(unbounded, 0))` | `df['col'].cummin()` (after sort) |
| `lag(col).over(Window.orderBy(…))` | `df['col'].shift(1)` |
| `.filter(…)` | `df[df['col'] == …]` |
| `.toPandas()` | already pandas |

The beat-the-champion transform is the most complex (4 joins, window rank for finals winner, cross-join pattern for WR-at-time). The notebook implementation is the reference — port function-by-function.

## First-time Setup

```bash
cd scripts/wca-refresh
poetry install
```

Then use `/refresh-wca` or `poetry run wca-refresh` from the cfop root.

---

## Output Format

NDJSON (one JSON object per line), matching the existing files exactly. The cfop-app parses these files at runtime; no schema changes.

---

## Gitignore

Add `scripts/wca-refresh/.wca-cache/` (or `.wca-cache/` at repo root) to `.gitignore` — the raw TSV export is ~300MB and must not be committed.
